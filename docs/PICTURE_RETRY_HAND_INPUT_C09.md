# 图片答错重试与手部交互修复

2026-09-17。用户反馈选项不明显，第二题回答错误后“变灰，然后不能交互了”，并要求答题可以用手操作得更便捷。本修订在第一站图片教学阅读面板加入真实手部近触，沿用共享凝视；其他普通面板仍按参考工程的既有分工。保持全程静音、Android / Meta Quest 配置和实际步行。

## 故障证据

错误提交原本会同时清空图片依据和判断。用户只修改判断时，依据仍为空，因此提交按钮保持禁用，视觉上像卡住。先用真实共享凝视补第二题回归：第一题完成、第二题选两个依据和错误判断、提交、只改判断、再次提交并进入第三题。`artifacts/vr-interaction/second-retry-red.xml` 的 1 项测试在“修改判断后提交按钮应可交互”处失败。

修复保留错误提交时的依据及判断，提示“已保留选择；请修改后重新提交”。用户可增删依据或修改判断，仍须满足本题完整依据和正确判断才可完成；没有自动给分或跳过。

## 交互与视觉

- 图片选区常显边框及实色编号标记，文字明确区分“未选／已选”，选中后增加蓝色填充。提交正确之前不显示正确答案。
- 判断选项使用高对比实色、选中描边，主提交按钮单独强调；缺少输入时直接显示“先选图片依据”或“再选一个判断”，答错后显示“重新提交”。提示区同时列出当前选中的依据及判断。
- 图片宽约 0.702 m、阅读距离约 0.62 m，保持约 59° 水平视角；按钮高度从 54 增至 70 UI 单位。展开后保持固定世界位置，手触不重新定位面板。
- 阅读面板接入现有真实 OVR 手部 PokeInteractor。手指进入可交互表面的接触范围时暂停共享凝视；撤离后恢复并重新计算凝视进度。手部提交仍需真实食指近触；未添加鼠标、射线、手柄或键盘入口。
- 实际 SDK 触碰测试还发现：按钮隐藏或禁用后，旧释放事件可能被可交互检查提前挡住，导致触碰提交状态未清除。现在先处理释放，再判断能否接受新按压；取消、撤离、禁用均释放接触状态。
