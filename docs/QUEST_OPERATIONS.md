# Quest 3交互与实机验收

> 当前0.6.0采用小场地六站教学，摇杆位移与转向已关闭，站间主动切换。以下保留历史交互设计；当前操作以[安装与测试](../安装与测试.md)及[六站版本说明](SIX_STATION_RELEASE.md)为准。

## 交付设备

交付体验为Quest 3独立APK。用户2026-09-15再次明确：医疗教学需要VR实操，不接受WASD作为操作方式。

头显内必须完成：观察空间、手柄选择/拿取检查对象、柜门开合、近距离查看、记录阅读与翻页、问题标记、区域转场、结果提交及复盘。桌面图像仅供制作人员检查构图，不能替代以上动作的头显验证。

## 操作设计

| 动作 | Quest手柄输入 | 验收点 |
|---|---|---|
| 指向选择/点击界面 | 扳机 | 两手均可；射线与点击位置一致 |
| 近距离拿取文件或可移动物件 | 侧握键 | 物件跟随手柄且可转动查看；不要求键盘 |
| 拿取后查看对应资料 | 扳机 | 内容与物件一致，关闭后仍能查看物件 |
| 柜门开合 | 选择门或门把手 | 门实际改变位置；柜内可达、可见 |
| 传送 | 指向地面并按右A/左Y | 不能落入柜体、墙内或工位内部 |
| 分段转向 | 右摇杆 | 头部位置为旋转中心，避免强制连续镜头移动 |
| 菜单与区域路线 | 左X | 菜单可关闭，操作不依赖开发电脑 |

此表是目标操作约定，实际实现状态以测试记录为准。用户澄清后继续要求以甲方文档为准，因此按监督检查找错实现上述交互；消毒剂说明书提供判定依据，不把它自动扩展为完整临床洗消操作训练。

## 实机验收顺序

1. adb识别设备并确认USB授权。
2. APK构建成功，核对包名com.endoscopy.inspection、ARM64和XR配置。
3. 安装启动；确认没有崩溃、Android二维窗口或XR加载失败。
4. 头显内双眼画面、头部跟踪、左右控制器和选择。
5. 拿取、放回、开柜、翻页及标记问题。
6. 五区完整教学与综合风险流程，最终回办公室汇总。
7. 性能与稳定性：实际头显运行采样；电脑截图和自动答题分数不计作帧率或实操通过证据。

## 构建路径

Unity Android工具不接受含中文的工程路径。tools/build.ps1会创建并验证D:\quest3\EndoscopyBuild目录联接，指向同一中文项目文件夹，通过ASCII路径构建。没有复制出另一个不同源码工程，也不移动或删除原项目。
