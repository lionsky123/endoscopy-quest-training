# 镜头一：现场关系与一次关门纠正（M04）

更新：2026-09-16。用户要求调整内容，避免旧包混淆和牵强关卡，并删除设备上的多余 app。本版替代三道面板题和示教盒搬运原型。

## 当前路线

1. 原房间全景先显示合规状态，门关闭、设备分别配置、工位完整。入口显示 M04、应用版本、实际构建标识。用户主动确认去门前。
2. 门前练习显示一个已有的未关门状态，Oppy 与定位引线指向实际把手。用户近距离握住把手，合回门框后松手，直接完成这一处纠正。没有“先把正确的门打开”任务，也没有答题或提交页。
3. 用户主动去设备观察位，看消化与呼吸的两台专用机及两侧槽组。可以近触实际设备查看用途和关系；这不是必做点击序列，不搬盒子、不移动大型设备。
4. 用户主动到流程观察位，沿实际槽位看清洗、漂洗、消毒、终末漂洗、干燥的顺向演示。可以近触各工位看对应说明，观察完主动去下一站。没有五次搬运、纸卡投放、回流问答或重复复查。

门操作按模型实际角度和松手判定。未关到位、只抓住又松手、远处捏合、追踪丢失都不计完成。设备与流程只记录观察进度，用户触碰实物或动画播放不产生“掌握”结论。

## 引导与边界

面板只承担短提示、按需说明与主动换站。全程静音、真实近距离食指操作面板，原房间和六站框架保留。站内真实走动、转身，不强迫头显俯仰或自动长距离移动。

无按钮的门段提示置于门扇前方的上侧可读区域，避免打开的门遮住文本。工具等其余五站旧交互不在本轮宣称完成范围。

## 防止版本再混淆

本项目固定 `com.endoscopy.inspection` / “内镜中心监督检查”。源码为 0.8.1 / M04；显式 Android 构建时递增内部 code、生成唯一标识；成功构建旁写入 `.receipt.json`，包含包名、版本、构建号、APK 路径与 SHA-256。入口展示实际构建标识，编辑器显示“源码预览”。

安装核验必须比对设备 APK 与明确候选包的 SHA-256。不能只比较显示版本号，也不能把上次下载副本当作当前设备证据。未更新设备时必须明确说明。

详见 [版本与设备操作记录](DEVICE_INTERACTION_DIAGNOSIS.md)。
