# 房间界面与加载过渡改版规格

状态：2026-09-24 用户确认的设计方向；本文件是专题规格，尚未表示 Unity 实施或 Quest 验收通过。

关联：[完整产品规格](FULL_SCRIPT_SPEC_20260920.md)、[内容矩阵](FULL_SCRIPT_CONTENT_MATRIX.md)、[专题实施计划](ROOM_UI_REFRESH_PLAN_20260924.md)、[原合并计划](STARTUP_FLOW_AUDIT_PLAN_20260923.md)中的 C01.E06/E07、M5.E05/E06。业务范围和任务完成语义仍按完整产品规格与内容矩阵执行；本文件定义本次界面改版的可观察结果。

## 1. 目标与依据

体验者在 Quest 中原地坐姿或站姿完成大厅选房、各房间观察、资料查阅、判断及办公室汇总。当前面板同时提供过多选项，一些任务需要重复进入目录、再按同义按钮；绿色主题、厚重卡片和统一矩形按钮缺少层次。用户还报告：Quest 切入各房间模型时会短暂黑屏，加载结束后房间正常显示。

本次目标是让场景和资料成为视觉重点，当前一步的可触操作清楚而少；全流程采用一致且更年轻的空间材质与颜色角色；从接受切房动作直到目标房间稳定显示，应用控制的过渡始终提供非黑色画面。现有宿主 Play 截图只用于定位旧布局，不代表 Quest 画面或本次改版完成。

## 2. 能力与边界

| 能力 | 提供的结果 | 主要消费者与依赖 |
| --- | --- | --- |
| 视觉角色 | 烟黑底、浅紫灰可触面、钴紫选中态、少量珊瑚反馈；统一字阶、边缘、深度和按下状态 | 欢迎、画廊、房间任务入口、电脑、文件、判断、汇总、声音设置；依赖现有 `ClinicalPanelStyle` 和欢迎主题资产 |
| 任务界面 | 按当前阶段显示入口、阅读或判断；按现场、电脑、纸质资料及其他真实载体组织；直接进入内容 | `FullScriptThemeSelection`、`FullScriptStationaryContent`、`FullScriptOfficeRecords` 及各房间专属界面；沿用会话任务状态 |
| 过渡连续性 | 切房及改变观察位时覆盖空间跳变；加载、追踪等待、失败恢复期间持续显示轻量预览与真实状态 | `FullScriptJourneyRuntime`、房间创建/释放和 Quest 渲染；沿用单房生命周期 |

三项能力可分别验证。视觉角色先形成共用基底；办公室形成完整入口、内容、返回样板后推广到其余房间；过渡问题优先做 Quest 证据定位，并在保持旧房释放顺序的前提下修复。不得用调色替代黑屏故障排查。

## 3. 已确认的视觉方向

![办公室面板视觉概念；非 Unity 实施画面](full-script-visuals/concepts/room-panel-smoke-lavender-concept-20260924.png)

上图是基于旧版正式 Play 截图加工的**概念预览**，只用于确认形态、质感与颜色关系；不是当前 Unity 或 Quest 的改版截图，也不是运行资源或验收证据。用户确认保留烟黑悬浮形态和轻薄材质，并让可触选项与背景明显分色。以下颜色是实现起点，须用 Quest 双眼画面调整，不能机械抽取概念图像素。

| 角色 | 初始方向 | 使用边界 |
| --- | --- | --- |
| 控件承托层 | 中性烟黑 / 深石墨，带克制的半透明和细边 | 只承载必要的近触操作，不铺成大面积遮挡房间的幕布 |
| 默认可触面 | 浅紫灰，文字深石墨 | 与承托层明显分离；未选和不可用状态可一眼区分 |
| 当前选择 / 主动作 | 钴紫底、浅色文字 | 同屏原则上只突出当前主动作；不把每个按钮都涂成主色 |
| 确认反馈 | 少量珊瑚色细线或短暂亮度变化 | 只在动作被接受时出现；不以持续发光代替可触提示 |
| 资料正文 | 不透明、低眩光浅底，深色正文 | 表格、电子记录和纸质资料优先保证字段关系、文字对比与缩放阅读 |

排版用明显的标题、对象名、状态、动作四级关系。控制面厚度和边缘细节应在立体双眼中可辨，但避免大范围折射、全屏模糊、强光晕与多层透明叠加；目标是 Quest 上稳定可读和低干扰。中文按钮写动作或对象，不能仅靠抽象图标。欢迎页保留现有简洁构图，更新共用色彩与细节；电脑、纸张、房间画廊和汇总各保留自己的载体形态，不统一成相同三卡菜单。

## 4. 用户流程与操作规则

1. 欢迎页仅显示欢迎、简报和“开始学习”。进入大厅后，房间图片本身承担选房；拖动、释放和新戳按的既有规则保留。
2. 进入房间后，首先看到当前房间可进行的少量业务入口。选择“电脑记录”等类别应直接打开对应阅读内容；纸质资料在文件载体内呈现；现场观察让主要模型保持可见。分类是为了找内容，不新增选择后再按“打开”或“开始”的确认页。
3. 查阅时只保留该资料所需的选择、缩放、翻页和单一返回路径；单页不显示翻页键。作答时才展开判断控件。当前任务、下一步与必要的跳过、未答、提示、回查入口依状态出现，不在每一层同时堆放。
4. 完成有效观察、抓取或查阅动作时沿用现有记录规则；打开资料或换视觉样式不能自动完成检查。最终办公室汇总仍统一提交，提交后只读。
5. “选择房间”是次要动作，在房间内保持可找到；切房请求只接受一次。面板第一次展开后固定在可视可达位置，阅读、切页和恢复追踪不贴头重置。

按房间组织的内容必须保留：

| 区域 | 入口组织与载体 | 不可丢失的内容 |
| --- | --- | --- |
| 大厅 | 欢迎、安小卫简报、环绕房间图片画廊 | 首次路线与回查，不把大厅列为检查关卡 |
| 办公室及最终复访 | 现场、电脑记录、纸质资料；最终汇总独立呈现 | 六字段、测漏与其他资料、判断修改、统一提交 |
| 储存库 | 柜体、柜侧登记、镜体对象 | 实物观察、原表结构、缺件状态 |
| 候诊区 | 座椅/隔断及两侧观察 | 双侧空间关系和当前观察方向 |
| 消化与呼吸诊疗室 | 设备、报告/历史、台面/废物按载体展开 | 两房证据和完成状态独立 |
| 清洗消毒室 | 空间与设备、水路、水槽视频、防护、产品、附件按对象及资料入口组织 | 六类任务、视频控制、缺件提示和有效判断 |

初始入口可把两个相关主题合在一个可触区域，但不能通过新增中转页来粉饰同屏按钮数。实施前记录每个代表页面的可操作目标数与典型任务按压数；改版后逐页对比。房间入口一般不超过三个同时突出的业务选择；资料中的真实字段、行和判断选项另计，不能为了达到数字隐藏证据。

近触必须区分悬停、主动按下、已接受与禁用；一次主动按压只提交一次。拖动画廊时和松手瞬间不能误选房；无凝视、准星、鼠标、键盘或控制器射线提交。手部追踪丢失时暂停交互并在恢复后重新确认当前动作。

## 5. Quest 加载与过渡

用户报告的黑屏出现在 Quest 各房间模型的加载阶段，结束后房间可显示；当前原因尚未在 Quest 上定位。现行代码已有绿灰过渡层与示意图，但这只证明代码意图，不能解释或否定实机黑帧。实施先记录黑帧开始/结束、是否伴随主线程停帧或运行时加载画面、当前源码与安装包身份，再修复对应路径。

从切房动作被接受到目标房间首个稳定帧、追踪真实就绪并完成揭幕，视野里应持续有固定在空间中的非黑色过渡面、目标房间预览和简短状态。读取资源、同步实例化、资源释放屏障、追踪等待以及失败/重试均不能露出纯黑底；不能显示虚构百分比或用定时器伪造追踪成功。同房检查点用更轻的同体系过渡。加载期间允许轻量常驻预览、UI、向导和会话数据；旧房对象及独占资源必须依次停止、解绑、销毁和释放后才创建目标房间，不同时保持两套房间模型。

如果同步资源加载使 Quest 停止提交帧，需改造加载调度或资源消费方式，让过渡画面在真实等待期间仍能提交帧；不能只替换遮幕颜色并宣称修复。失败应保留会话、释放失败目标，显示可执行的重试/恢复操作；不把失败目标记为已访问或已完成。房间预览必须与目标对应，现有插画图集尚非每间实际模型的验收凭证。

## 6. 可验收条件

- 当前任务相关的入口、阅读、判断和反馈不互相堆叠。办公室、储存、候诊、消化、呼吸、洗消、最终汇总和欢迎/画廊逐页有改前/改后控件清点与常见任务按压路径；重复按钮减少，典型任务步骤不增加，优先至少省去一处无业务意义的中转。
- 整套界面使用确认的颜色角色与材质层次，主动作清楚；中文长短文案、禁用/选中/按下态在 Quest 双眼中可读。电脑与纸面正文不因玻璃化而降低可读性，不遮挡需要观察的对象；坐姿和站姿近触可达。
- 跳过、未答、提示、判断修改、缺件、失败重试和提交后只读仍可找到且语义不变；房间切换、面板重开和丢手恢复没有双触发或额外完成记录。
- Quest 中从大厅进入每个房间、跨房回查、慢加载、追踪等待、失败/重试与同房检查点过渡均有连续的非黑色画面；场景切换只在遮蔽空间跳变时对齐环境，头手保持 1:1；单房释放与内存边界保持。
- 代码变更后在当前 Unity 工程以 Android 目标实际导入/编译通过，并做改动相关局部测试。正式 Play 画面、Quest 双眼/手部与性能分别报告，不能互相代签；用户负责最终完整流程验收。

## 7. 实施约束与非目标

工程为 `app/`，Unity 6000.3.23f1，Android / Quest；现有 C# 运行时与 Unity UI/TMP、近触输入、单房释放流程均复用。项目模型仅允许既定 `C:/Users/i1204/Desktop/Models` 来源，且模型贴图修正由另一对话负责；本次不重新导入、重绑、重贴图或修改房间模型材质。不改医疗依据和评分、不新增行走或输入后备、不恢复大厅高斯模型、不构建 APK、不擅自操作头显。

文档中的概念图仅供风格参考，实际效果必须由改版后当前工程的正式 Play 和 Quest 画面分别验证。缺件、医学依据未核实和实机未验收均保留原状态。
