# C09 教学调整：动手任务为主，减少独立答题

2026-09-18 甲方新增反馈：希望增加互动、减少答题。本文件记录下一轮教学设计与实现范围；不代表 Unity 已完成下述改造。当前可运行版本仍见 VR_HAND_FIXED_C09.md，其 53 项通过记录不用于证明本方案已实现。

## 体验目标

把“看媒体 → 选答案 → 提交”改为“小精灵提出具体任务 → 用户观察和操作 → 场景呈现操作结果 → 简短解释 → 下一站”。保留六站路线、实际步行、固定房间、全程手部、静音和短暂的小精灵对话。

建议六站不再各自安排独立选择题；最后最多保留一次可跳过的简短复盘。是否完全取消最后的选择题尚待用户反馈。操作与观察占主要体验时间，目标约 80%；这是设计目标，不能当作已测得的数据。

评价学习效果的依据改为对象状态和操作关系：是否放到对应位置、是否完成匹配、是否查到证据缺口。不要通过把答案按钮改名为物体来充当空间互动，也不要靠观看时长或任意触碰次数自动判定掌握。

## 六站设计

| 站点 | 具体任务与可见结果 | 完成依据 | 资源与范围 |
| --- | --- | --- | --- |
| P01 空间巡查 | 保留 360 全景和三个观察点。把检查标记拿到门洞、两组设备等目标的特写位置；放置后显示局部轮廓与检查要点。第三点沿工位方向展示流向，用户触碰起点启动演示。取消每点的符合/不符合和提交。 | 门的观察位置已找到、两组设备均已查看、流向演示已触发；反馈只说明观察到的内容，不据此认定整体合规。 | 复用全景和图片，标记使用空间 UI。全景图片本身不能开门，不宣称已实现实体关门。可开合模型属于后续资源条件，不恢复归档主线。 |
| P02 流程实验台 | 抓取五张工序牌，放入五个顺序槽位；放错时指出相邻关系，牌仍可拿起调整。排列完成后，一个示教物沿工位依次移动，直接展示单向流向。取消原第二道处置选择题。 | 五个位置与项目既有流程配置匹配，释放后稳定吸附；自动进入结果演示，无提交按钮。 | 复用现有五环节数据。工序牌和槽位是教学 UI，不冒充真实设备；不模拟具体洗消参数。 |
| P03 工具准备 | 视频作为可暂停、可跳过的观察材料。把五类工具放到准备区中对应的位置，缺失位置以空槽提示；补齐后准备区由未齐全变为齐全。 | 五类工具各归位一次，按类别核查而非总数。 | 现有视频不是五类工具全套。首版可用注明名称与来源的图片物件；真实模型须另行从网络获取并保留许可，不手绘替代。不能把通用视频中的任意器械当作目标工具。 |
| P04 状态检查 | 把毛刷图片物件拿近观察，再将破损样本移入“停止使用”区；随后沿水路证据节点逐个打开检查，将缺记录的节点挂上“待核实”标记。结果同时呈现已发现的破损与证据缺口。 | 破损样本已归入处理区，水源、滤膜和记录均查看，缺记录节点已标记；错放可取回。 | 复用毛刷图与三页证据。首版水路是明确标注的教学关系图；没有真实管路资源时不宣称完成实体接管、滤膜拆装。 |
| P05 产品核查 | 拿起并旋转现有瓶体，放入检查托盘后展开资料；把对应身份、用途和材料资料放入匹配槽，再把尚未核实的具体型号兼容性留在待核实区。 | 资料与对应样本关联正确，兼容性缺口保留；拿起或转动瓶体本身不算完成资料核查。 | 现有瓶体 X-01 为通用模型。资料样本 YJ-01 与它明确分开，不把通用瓶体包装成真实产品；不能用 YJ-01 资料证明 X-01 适用。 |
| P06 记录追溯 | 将使用记录与登记条目逐一配对；匹配成功后出现连线，无对应项进入待核实区。再把附件包装与批次记录尝试对应，将缺失批次的对象标记为待核实。完成后展示本次发现清单。 | 完整给定范围内的记录匹配正确，缺失记录和批次关系被识别；禁止凭空补造编号。 | 复用现有模拟台账与附件情境，不新增患者资料。若保留最后一次简短复盘，放在发现清单之后，且不阻塞离站。 |

P01 侧重空间观察，P02 侧重顺序摆放，P03 侧重工具准备，P04 侧重检查与处置，P05 侧重拿取和资料关联，P06 侧重配对追溯。避免六站全部变成同一种拖卡题。

## 操作与引导

- 一次只出现当前操作需要的物体与目标，不把整套关卡内容铺满视野。工具或记录较多时分批提供，但完整任务范围必须可查。
- 小精灵使用现有参考对话框，每次只说明一个动作和目的，例如“把这张工序牌拿起来，放进你认为合适的位置”。首次成功后收起示范；停顿时给短提示，不常驻教程。
- 可操作对象有清楚的边缘提示；手接近、抓取、目标可接收、放置成功各有不同视觉状态。空间物件只接受手抓取，普通按钮只接受近触，不恢复凝视或射线。
- 面板继续使用已验证的前方约 50 cm、眼下约 18 cm 初始位置。抓取物、落点在当前手部可达区域内分布，避免让用户穿过面板取物；具体范围须在头显上验收，不以桌面截图声称舒适。
- 放置以真实抓取释放和目标范围判断，释放前不计完成；只有匹配对象进入槽位才吸附。错误对象保持可操作并给出原因，不变灰锁死，也不把整关清空。
- 房间、路线和任务台固定。手持物可移动；掉落、丢失或超出范围的物件回到本任务的固定起始位，不拖动房间、面板或用户。
- 去掉常驻“选答案”“提交”和冗余“继续”按钮。完成一次有效操作后给短反馈，再自动呈现下一步；为避免同一只手误触，下一步需撤手后才重新接受输入。
- 保留一个“跳过当前任务”入口，跳过直接进入后续流程且单独记录。保留媒体必要的播放/暂停；取回按钮只在确有需要时出现。末站结束仍接现有主动离站逻辑。
- 结果展示“已完成操作 / 待核实发现 / 已跳过”，不以答对题数主导页面。提示和示范不冒充独立完成。

## 工程改造边界

现有 ClinicalCourseSession 只按选项、排序答案和证据阅读判断完成；模型的手部抓取尚未参与任务完成条件。实施时需要增加独立的操作任务状态与对象关系验证，不能只修改 course.json 的标题和按钮文案。

建议配置把媒体形式与任务规则分开：全景、图片、视频、模型用于呈现；观察标记、顺序放置、分类归位、关联配对用于任务。共享抓取/释放/吸附组件，按关卡配置完成关系，仍由原内容会话发出一次完成通知。

先实现 P02 抓取排序和 P05 拿取/资料关联，验证真实手部释放、错放重试及下一站衔接；再复用到其余关卡。P03 缺少专用模型时允许图片物件搭框架，素材欠缺须记录，不以无关模型凑齐合规场景。

## 验收与当前状态

- 每关至少一个可直接观察结果的操作；不能用点开所有说明页代替主要任务。
- 真实手部测试覆盖抓取、移动、释放、槽位吸附、错放取回、跟踪丢失和重入；禁止仅调用按钮回调作为完成证据。
- 纯凝视、靠近但未操作、任意转动模型、未释放的物件都不能完成需要放置/匹配的任务。
- 逐关验证正确完成、错误后修改、直接跳过、末步跳过及完成通知去重；全部可以继续到下一站。
- 保留固定世界与面板回归、六站步行、界面互斥和全程静音检查。
- 本次仅形成教学调整规格，尚未改动运行时代码或资源配置；没有新增运行测试结果。后续只做必要的静态与 Android 目标编辑器验证，用户自行编译 APK。
