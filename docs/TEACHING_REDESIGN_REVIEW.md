# 教学呈现与站间流程改版访谈

状态：三轮设计选择与整体执行均已确认，用户已回复“开始执行”。完整方案见 [有效 spec](PANORAMA_LESSON_REDESIGN.md)，本次工程交付见 [实现记录](PANORAMA_LESSON_IMPLEMENTATION.md)。以下保留访谈当时的核查、选择与候选方案；其中“尚未实施/待复现”为当时状态，不能覆盖最新实现记录。

## 用户本轮反馈

1. 完成本站学习后不能进入下一站。
2. 内容单一，质感和教学性不足。
3. 多个面板与教程堆叠，排版混乱。
4. 图片可以更大，并希望用图片出题，而非直接展示正确与错误。
5. 希望探索更有表现力的图片呈现方式。

## 已核实的设计现状

- 第 1 关当前为房间观察、门/设备/流程六张特写与正误对照、最后三道题。参考 FIRST_LESSON_ROOM_OBSERVATION.md；这意味着答案线索在独立作答前已经直接揭示。
- 当前工程沿用凝视面板、手部空间对象、静音和实际步行。图片变为题目不自动改变这些已确认要求。
- CONTEXT.md 将“核查判断”定义为依据现场事实作出结论，选择一个对象本身不是完成判断；“检查向导”在独立核查期间不应提前揭示异常位置。
- 只读核查发现高优先级待复现路径：答题确认关闭后，StartupRecallPresenter 仍满足 closed + HasPreviousContent，可能恢复旧关闭决策面板；完成分支的 ClearJourneyPrompt 在没有 journey prompt 时不处理该面板，CloseDecisionVisible 又令导航保持暂停并隐藏 Departure。现有六站测试使用替代 prompts 与默认环境，未覆盖这组真实 UI 互斥。此项是代码链路发现，尚未执行失败复现，不能声称已经修复用户故障。

## 第一轮已确认选择

- 教学顺序 A：先示范检查方法，再在没有答案标记的新情境中独立判断。见 ADR 0002。
- 图片呈现 A：空间取景窗；用户要求增强 VR 体验，第二轮明确保留 360 全景主教学空间，不迁移到三维模型主教学。
- 改版范围 A：先修六站共用的换站与堆叠，再完成第一站样板，定型后推广。

## 方案与候选表现

### 教学顺序

推荐“简短示范检查方法 → 未标答案的新情境大图 → 用户指出依据并判断 → 作答后揭示标注与解释 → 变式巩固”。另一种选择是直接案例挑战，再通过错误反馈教学。关键区别是是否为新手提供作答前的方法示范，而非是否提前给出同一道题的答案。

### 图片呈现

- 空间取景窗：在房间工位旁展示一张大幅现场图，边框与文字克制；选中细节后在当前画面放大，作答后叠加证据标注及局部前后变化。推荐为主要形式。
- 双场景揭示：同一视角的两个情境先隐藏结论，作答后以分割线或擦除过渡显示差异。适合对照类内容，不用于每题固定“左对右错”。
- 证据台：围绕当前检查任务呈现少量设备照片、标签或记录局部，让用户结合证据判断。适合产品与记录类内容，控制证据数量以免再次堆叠。

上述为原创候选设计，不声称平面照片经过动画即成为可自由走入的真实三维空间。

### 界面收敛

建议每个阶段只有一个主要可交互教学界面；向导提示并入同一画面的字幕或短句区域。观察、作答、反馈、出发按状态切换，阶段结束彻底收起旧界面。堆叠修复必须覆盖实际状态链路，不能仅靠把面板放得更远。

### 改版范围

推荐先修六站公共的离站链路及界面互斥，再用第 1 站验证完整的新教学体验，定型后迁移其他站。替代选择为六站同时重做。

## 第二轮已确认选择

- Q4 B：保留 360 全景主教学空间。用户强调全景的包围感与转头观察本身就是 VR 体验。本轮不做三维工位状态教学改造，见 ADR 0003。
- Q5 A：答错后先给观察方向，再逐步增加提示，让用户重新寻找依据和判断；不看完答案便直接计为掌握。见 ADR 0002。

## 第三轮已确认：全景中的观察与图片判断

用户回复“按照你推荐的”，确认按全景中的实际方位组织观察主题，转头寻找相关区域，再通过明确的凝视确认展开一张大幅证据图。展开动画从对应方位发起，最终稳定为便于阅读的大图；关闭后回到原全景方位。主体始终只有一处可交互教学界面，小精灵文字并入其中。

图片作答以先选择关键区域、再作判断为主，状态对照适当采用候选图片选择。定位选择使用中性反馈，不能提前用红绿暗示答案。图面不接受仅因普通阅读停留就直接提交整题，需有明确确认步骤。不同区域进入选中状态不另弹面板。答后讲解用原图局部放大、轮廓和关系线逐项揭示，不并排长期展示正确/错误答案图。

已确认：Q6 A，转头定位，找不到时提供方向提示；Q7 按推荐组合，图中定位与判断为主，图片对比为辅。

既定凝视/手部分工、静音、实际站间步行继续保留，不重复询问。窗口尺寸与距离将按大图可读性和凝视交互实现，不机械地把整幅大图贴到原近触距离。尚未修改本轮运行代码、生成新教学素材或构建 APK。

## 只读链路核查补充

全局 Modal 当前抑制普通 shell 与 Startup，但没有直接抑制 ClinicalPanoramaControls；首次全景进入又可能触发独立的 Coach 退出教程。由此允许全景学习卡片与 Coach 对话并存。第一站自身 PanoramaTutorialHint 已被隐藏，不能把它误判为叠加来源。需用首次进入、教程未掌握的状态复现，并验证整个教学阶段只有一个主交互界面。

## 素材核查事实

三张 lesson1-*-comparison.png 均为 1672×941，已烘焙正确/错误标题、固定左正确右错误排列及红绿标记；流程图还直接包含方向箭头。隐藏 UI 不能将其变成未标答案的新情境，裁掉标题也不足以消除流程图的答案暗示。

cleaning-room-360-v2.png 为 7680×3840，可以保留。当前“现场特写”是 RawImage 对全景做 uvRect 矩形截取，没有透视校正；大图显示时应核对投影失真。现有图片框约 0.525×0.282 米、距前方 0.45 米，正误案例又各占半幅，影响观察细节。

最小素材方案：三个主题各新增一张独立、无正误标记的新情境图；原图保留为讲解素材。题干、选择区、分级提示和答案标注由独立显示层管理。无需重新制作完整全景，也不恢复图鉴和图片选择目录。
