# ADR 0005：房间转场采用准备—提交接口

- 状态：已接受
- 日期：2026-09-21
- 范围：完整剧本 P2 房间转场基础层

## 背景

房间切换不是把 `CurrentRoomId` 立即改成目标房间。实际 Unity 转场还要完成淡出、旧房间资源清理、目标房间加载与哈希校验、入口对齐、激活和淡入。若在这些步骤之前就修改旅程状态，加载失败会留下“会话认为已进入新房间、画面实际仍是旧房间”的不一致。

## 决策

`ClinicalJourneySession` 对门口请求先生成一次性 `ClinicalJourneyTransitionTicket`，但不改变当前房间、已访集合或主线游标。`ClinicalRoomTransitionCoordinator` 将转场保持在 `Loading` 状态，Unity 房间适配器完成目标房间的加载和激活后才提交 ticket。

- 成功加载：提交 ticket，推进当前房间、已访集合和主线游标。
- 加载失败：适配器先恢复旧房间，再取消 ticket；协调器进入 `Failed`，必须显式恢复后才能重试。
- 迟到或重复回调：用 ticket 的序号和起止房间校验，不能提交当前转场之外的请求。
- 会话仍为内存状态；转场失败恢复不引入跨应用持久化。

## 后果

房间加载实现可以是同步或异步，也可以替换为灰盒/正式资源适配器；旅程规则和 Unity 生命周期不互相污染。代价是 Unity 适配器必须遵守“失败前恢复旧房间、成功后再回调”的接口约定，且实际门口近触、淡入淡出和资源生命周期仍需下一阶段接入与头显验收。
