## 采用的安排

参考依据为原工程 `docs/adr/0001-gaze-panels-hand-objects.md`、`docs/superpowers/specs/current/experience-and-frontend.md` 及对应运行代码。模板从初遇对话起统一普通面板输入，手部集中于开场和空间物体。当前工程沿用这项分工，不恢复已取消的图鉴、掌心工具或地图召唤。

| 位置或操作 | 本工程交互 |
|---|---|
| 开场印记/邀请 | 保留模板真实手部操作；没有可靠手部追踪时，沿用 5 秒后的凝视后备 |
| 小精灵初遇对话、重看、到站、出发 | 头向准星对准按钮，停留至进度完成 |
| 第 1 关“开始观察”、六张图谱的继续及开始答题 | 同一个凝视继续按钮；按原顺序逐张加载 |
| 普通全景操作、图片查看与返回 | 模板共享凝视输入及进度反馈 |
| 答题选项、确认、返回及结束确认 | 凝视停留；答错可重新选择，保留最终解释确认 |
| 保留的空间物体直接操作 | 真实手部；操作持有输入暂停令牌期间，背景面板不能提交 |
| 小精灵导航 | 仍读取 VR 中玩家实际位置，实际步行跟随；出发确认不传送玩家 |

普通面板不同时接受拍打与凝视提交。凝视指头显朝向中心准星，不依赖眼动追踪；共享 `HeadGazeDwellController` 的 0.65 秒计时与 0.2 秒短暂丢焦宽限。确认后、页面改变、可见性或上下文变化时取消旧进度，必须移开再对准才可再次提交。手部只被识别出来，不会因此禁用正常凝视；实际空间操作期间才暂停面板输入。

普通面板触发时保持此前已调整的前方约 0.45 m；同一阅读会话内保持世界位置。前倾、焦点反馈、状态提示刷新及同会话翻页不重新按当前头部位置放置面板。新对话或新内容会话按当时视角放置，不移动玩家。

## 面板后移的复现和修复

使用生产 `VisitorRuntime` prefab 的 `StartupRecallPresenter` 建立回归：先显示面板，再让模拟观察者前移 0.35 m、转头 35°，分别刷新 Closed 状态与更新旅程状态。两条路径都调用原定位逻辑，面板位置偏移约 0.373 m。

- 修复前命令：`tools/test_vr_interaction.ps1 -Run panel-shift-baseline -TestFilter VisiblePanelKeepsItsPoseWhenAnActionRefreshesStatus`。两项失败，位置偏移断言记录约 `0.372526884` m。
- 原因：已经显示的面板在状态刷新时再次执行 viewer-front 定位；伸手时常伴随前倾，刷新会把面板移到新的头部前方。
- 修复：在当前关闭内容/阅读会话中保存已放置状态，提示刷新和临时遮挡沿用原姿态；新内容生命周期及解除配置清除记录。
- 单项修复检查：`tools/test_vr_interaction.ps1 -Run panel-shift-fixed -TestFilter StartupRecallPresenterLifecycleTests`，8/8 通过。

这是已复现并修复的代码路径，尚未以 Quest 实机复现用户每一次“拍后后移”的具体过程，不据此声称硬件问题全部验收。

## 实现范围

- 恢复模板共享凝视控制器的每帧输入，不再周期性给所有面板注入 `ClinicalNearTouch`。
- 恢复开场状态的准星显隐、对话与引导的 HeadGaze 输入模式及无可靠手时的邀请后备。
- 普通面板的序列化按钮恢复模板 Button，动态学习、全景、图片查看控件采用同一按钮与凝视注册机制；不新增第二套计时器。
- 动态学习按钮复用模板进度条；翻页使旧进度失效，0.42 秒切换期间禁用继续，持续注视不连续翻页。
- 生产对话保留手部目标的生命周期清理，但凝视模式下关闭其触碰体；焦点反馈不平移按钮命中面。
- 同步开场与学习提示文案。答题中发现的长选项溢出通过文字区域 104 px 高、固定 24 px 字号及减少重复内边距修正；按钮位置与命中尺寸不变，完整保留原题目。
- 同步工作区、项目及 app 的 AGENTS、SPEC、README 与第 1 关规格，明确覆盖历史仅手触规则。
