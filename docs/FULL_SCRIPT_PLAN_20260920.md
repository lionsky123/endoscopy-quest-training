## 13. 单房间加载与资源释放实施细则

默认事件顺序：`DoorRequest → CloseInteraction → FadeOut → DisposeRoom → ReleaseRoomAssets → LoadTarget → ValidateTracking/Geometry → Commit → FadeIn`。旧房未释放不得开始新大模型加载，当前运行时的Destroy延后一帧本身不足以证明贴图/网格资源释放。

1. 房间目录只持有字符串ID/资源定位与版本，不以一个常驻ScriptableObject直接引用全部大Prefab。新增原始/整理模型留在非Resources目录，正式发布时明确每房间依赖集合。
2. 通过当前房间装载接口取得房间根、地图、锚点和释放句柄；视觉模型实现可以是处理后的Unity房间或已验证的大厅高斯适配，不让会话模块了解渲染格式。
3. 共享向导、手部、小型UI独立持有；房间相机/视频纹理/材质实例/工具等由房间所有者释放。仅当前任务需要的高分辨率特写/视频按需取用，关闭后解除引用。
4. 转场之前先阻止新交互；停播视频、取消抓取、解绑事件和异步回调，等待旧房间销毁，再释放资源。异步结果带房间代次；迟到完成只释放自己资源，不污染新房间。
5. 失败目标先清理，再恢复原房间；保存会话业务检查点而非旧GameObject、旧抓取或旧头手姿态，不通过常驻第二个房间获得“回退”。
6. 回访重新按需装载相同房间，恢复本次会话证据/判断/学习进度；应用关闭后全部进度丢弃。
7. 校验同一时刻活动房间实例≤1，独占重型加载句柄不重叠；循环A→B→A后无增长的对象/材质/纹理持有。Quest记录加载前、卸载后、新房进入后的内存与时延，不仅比较屏幕可见性。
8. 不为了“优化”等待而默认预加载第二间；如未来考虑变更，要先提出实测理由并获得用户确认。当前不新增外部资产管理依赖，也不自动构建AssetBundle/APK。

## 14. 开发预留的实现方式

- 数据层：逐检查子项保存availability与blockedReason；正式内容加载前校验对象/证据/规则。开发状态允许MissingAsset等条目存在，不给它伪造正确答案。
- 场景层：缺项只留清楚的作者锚点/替换插槽；玩家可到本室其他点位继续，不以大块空白面板当作实物资产。暂不可用提示仅在触发对应任务时出现。
- 会话层：只记录真实用户动作；内容缺失不会调用TrySkipGuidedTask，独立不可评不等于答错。LeaveIncompleteTasks已改为仅离站，不自动跳过/未答；显式跳过仍独立记录。
- 汇总层：开发体验提示“已学、主动跳过、未答、暂不可用”；完整发布未Ready内容不允许通过发布检查，但允许结束开发体验。提交事件冻结已有记录，不把未交付任务补成完成。
- 替换层：收到模型/视频/资料后只替换对应资产/证据和可用性，不重做整条主线，也不修改其他房间进度；替换后运行本项和跨房回归。
