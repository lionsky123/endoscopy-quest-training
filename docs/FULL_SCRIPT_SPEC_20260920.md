## 4. 房间切换与实际场地

### 4.1 切换入口与过程

已确认交互（D02）：完成房间学习或明确处理未完成项后，小精灵引导用户实际走到房门，在门口近触“前往××”按钮，再淡出切换。房间总结页只启动去门口的引导，不能直接切换房间；门口按钮须位于当前可走活动区内。计时结束、视线停留或接近门口均不能自动切换。

教学关门与房间切换是不同操作：新稿N04通过门体真实关闭状态完成教学；用于离开的门口按钮只提交房间切换请求，不替代关门，也不因开关门动作自动换房。门口按钮与把手须有清楚的交互分区，防止一个手势同时关门和离开。

切换过程必须满足：

1. 同一时刻仅受理一次请求；确认目的房间存在、资源可用、路径与模型匹配，在本次运行的内存中保留当前会话及恢复检查点，不写跨重启进度。
2. 关闭原房间主面板、全景、取景窗和视频；取消真实抓取并收起房间内工具，不能携带旧交互回调进入新房间。业务证据记录继续保留。
3. 淡出到不展示空间跳变的过渡画面，加载并验证目标房间；只在过渡阶段进行进入姿态对齐，禁止可见状态下拖动或旋转用户镜头。
4. 可靠头部追踪、头手一致的定位、有效地面和活动区验证通过后，一次性进入目标房间的入口状态；真实站立高度、俯仰和侧倾保持不变。
5. 淡入，显示目标房间名称和本房间任务，再开放手部输入、小精灵和到站检测；此前的未结束触碰必须先解除，不能穿透成下一页点击。
6. 失败时保留当前内存进度，提供重试或返回可恢复房间的入口；不得黑屏卡死、误记目的房间完成或自动跳过缺失内容。

实现必须区分两类坐标变化：系统追踪原点改变时的补偿，以及用户主动跨房间时的进入对齐。当前 `VirtualRoomTrackingOrigin` 只面向单房间首次对齐，不能在多个房间分别重复订阅同一事件、叠加补偿或让旧补偿撤销新进入姿态。

### 4.2 可走范围与场地适配

房间切换不改变人在现实中的位置，也不把人自动带回实际活动区中心。若人在边缘切换，却把他当作处于一块新场地中心，下一次引导仍可能越界。

每个房间需发布：入口、活动区边界、必须到达的观察位、站点间路线、站立及伸手余量，以及与部署场地的对应关系。不能仅检查小精灵路径无碰撞就宣称玩家路线可用；虚拟碰撞体也不能阻止玩家身体穿过虚拟墙。

- 实际移动与虚拟移动保持 1:1，不缩放玩家身体/步长，不在走动中旋转或平移整个房间以绕开边界。
- 优先复用同一现实活动区布置各个房间，选择与用户当前实际位置匹配的入口姿态；不满足活动区条件时暂停进入并给出明确恢复步骤。
- 系统安全边界保持可见。若工程无法取得可靠的边界几何，不声称可以自动验证；使用部署时实测并配置的活动区，记录其来源和适用设备。
- 场地适配仅需部署配置，不自动恢复 MR 扫描或管理员标定主线。
- 当前洗消室外轮廓约 15.8×7.6 m、六站路线约 32.32 m，来源为 [C09 房间规格](VR_ROOM_C09.md)及[路线绑定记录](VR_ROOM_PATH_BINDING_C09.md)；这些是虚拟模型数据，不是实际场地测量。
- D03已确认“实际场地未定”。可开发转场、内容和房间灰盒；不得填写假定的最终场地尺寸、冻结最终房间布局或宣称全房间实际可达。门口同样属于必须实际到达的位置。
- 若场地容纳不了原房间，先提出能保留业务关系的活动区重排方案；室内分段传送、缩成桌面模型、放大步长或删站均不是已获授权的替代方案。

### 4.3 房间内导航和面板

每个房间有自己的模型、地图坐标和小精灵路线。开场与对话停留点落在本房间有效路径上；找不到返回路线就暂停提示，不穿模型直切。仅突出当前目标，保留已确认的主动继续/离站。

普通面板沿用约前方 50 cm、眼下 18 cm的初始布置，面对用户后锁定。翻页、重试和提示刷新不得重新贴脸。文档细节可在固定特写面板阅读，但任务结束回到同一室内位置，不利用特写实现室内移位。

## 7. 课程、证据和会话规则

课程采用“旅程 → 房间 → 教学站 → 任务 → 证据”的组织关系。房间数量、教学站数量、任务数量、标注数量和记录字段数量互不等同，不能沿用固定五课、三选项、三证据卡的限制。

需要支持的任务表达包括静音对话、三维观察/必要对象操作、图片区域教学、记录字段核查、本地视频、人员部位教学、产品/资料关联；现有排序、图片判断和台账对账按内容映射保留，不强制给每个知识点附加选择题。

当前体验方式（D05，2026-09-23修订）：

- 正式体验只有全程引导学习，入口直接“开始学习”，取消独立核查与模式选择。
- 安小卫逐步引导观察、查阅、对象操作与依据判断；由体验者主动操作，不自动完成任务。
- 全程保持原位，通过真实手部切换房间和检查点；无需步行、到门口或跟随角色移动。环境仅在遮黑转场内对齐。
- 保留完整正常/异常情境与同源证据，不因取消独立模式删减教学内容。

- 每个任务声明完成依据：阅读后主动继续、所需区域逐项查看、门达到目标状态、核查提交等，不能用统一“看过=答对”。
- 任务状态至少区分未开始、进行中、已完成、已跳过；核查结果另存未提交/正确/待修改。不可用资源记为阻断原因，不冒充跳过或完成。
- 引导学习允许主动跳过或暂留未答后继续到其他房间，结果中列明跳过、未答和漏检，均不计为正确（D07）。跳过不自动点击离开或切换房间。
- 房间状态由必修任务及其明确处理结果汇总；“房间流程结束”和“全部要求已掌握”不是同一结论。
- 复访保留证据查看和作答记录，防止重复计数；学习记录在办公室统一结束前可回查修改，提交后只读复盘（D08）。重新开始新会话清空当前答案、提示、对象情境与汇总。
- 同一镜号、模拟患者标识、产品、日期、批次及报告在办公室与现场共用同一证据记录；截图、三维标签、表格和结果页从同一数据生成或校验一致。
- 正式内容资源缺失、来源未核实或判定规则未定时，开发版本可以明确占位，正式完成检查必须阻止把它算作通过。
- 应用每次重新启动都创建新进度；不保存跨重启会话，不显示“继续上次”入口，不恢复上一次的房间、答案、抓取、位姿或结果（D06，按用户最后补充）。房间切换与复访在同一次运行内保留会话；同一进程的短暂暂停/摘戴先暂停交互，恢复追踪后继续本次进度，不等同于重新启动。

### 7.1 复访、统一提交与新进度

主线按D04顺序全程引导。用户保持原位，通过手部按钮进入下一房间或复访已到访房间，无需到门口。最终办公室汇总已学、跳过、未答及暂不可用项目，可回查后明确结束学习；结束后只读。每次应用重启创建新会话。

### 7.2 分幕式引导探索规格（2026-09-23访谈确认）

#### 目标、范围与决策依据

面向原地坐姿或站姿的培训体验者，将当前说明面板与重复翻页为主的流程改为“进入现场—选择检查对象—观察/操作/查证—获得反馈—主动继续”。成功意味着用户清楚知道当前检查什么、如何操作和下一步去哪里，场景与资料占据主要视野，安小卫能够结合实际行为持续带教。

访谈已确认：引导式探索；保留完整现场；有效操作自动记录、即时回应但主动继续；首次示范后尝试；按房间分章、主题分幕；前方弧形近触入口；对话与操作衔接；改变选择时就地带教；判断错误先提示再重试。用户随后补充：医院大厅用作游戏式初始大厅和章节选择背景，不作为可选章节/幕。这里描述一个统一的分幕体验能力，以下职责用于界定其协作边界，不新建并行模块规格或第二份任务清单。

| 职责 | 提供的信息或行为 | 依赖边界 |
| --- | --- | --- |
| 会话与内容 | 当前房间/主题/任务、可用性、证据、方法教学状态、行为记录和判断 | 既有业务数据及适用依据；不依赖某个UI是否显示 |
| 分幕选择 | 推荐目标、可选择检查点、主题回查和继续入口 | 读取会话与内容；发出主动选择意图，不自行判定完成 |
| 场景交接 | 收起输入、切房释放、遮黑对齐、追踪就绪、失败恢复 | 接收选择意图；成功后才更新有效位置，不依赖对话播放完毕 |
| 安小卫与界面 | 台词、提示、动作反馈、资料和观察界面的互斥 | 读取当前任务及有效行为；不能靠台词结束、动画结束代签任务 |

#### 用户流程与内容映射

入口只有“开始学习”。医院大厅使用用户提供的360°全景作为初始游戏大厅背景，承载欢迎、安小卫简报和开始入口；开始后可在该背景上呈现章节选择，不需要先进入一个“大厅检查关卡”。完整路线保持：大厅入口 → 办公室 → 储存库 → 候诊区 → 消化诊疗室 → 呼吸诊疗室 → 清洗消毒室 → 办公室汇总。

章节选择只列业务章节，不列“医院大厅”卡片或可选幕，不给大厅设置检查进度、完成星级或任务清单。N00仅保留为非评分简报/进入事件，不要求单独点击“完成大厅”。首次“开始学习”衔接推荐的办公室章节，不能为了章节选择再增加一次无意义的“选择大厅—进入大厅”确认。

大厅章节选择承载可进入的主线目标和同次会话已到访章节的回查，不默认解锁未到访章节；回到该选择界面也不重置会话。大厅背景是该界面的环境，进入业务房间前仍按单房生命周期释放，不把大厅全景作为全程常驻背景。章节选择与房间内的主题/检查点选择分属不同层级，不同时堆在一个环绕菜单里。

一次房间访问的流程为：`入室呈现场景 → 安小卫简短导入 → 当前主题的弧形选择 → 主动进入检查点 → 观察/操作/资料核对 → 反馈与可选重试 → 返回主题选择或主动继续 → 房间小结 → 主动切房`。允许跳过、暂留未答及回查；这不是必须逐按钮确认的固定步骤串。

业务房间是章节，主题是幕，检查点是幕内可选对象或观察位置；医院大厅是章节之外的入口与选择背景。主题划分不得删减或合并签收原任务子条件。下表是规格层的内容归组，精确入口数量、主题名称和观察位在后续设计中结合资源核实，不把推荐顺序做成未声明的强制依赖。

| 章节 | 主题归组 | 原业务映射 |
| --- | --- | --- |
| 初始大厅（非章节） | 欢迎、任务简报、开始与章节选择背景 | N00仅为非评分入口事件；使用用户360°全景，大厅不出现在可选章节中，不恢复旧开场链 |
| 办公室首次 | 办公现场；电子记录；纸质资料与产品档案 | OF-00–OF-05；保留六字段、逐次对账与六类资料 |
| 储存库 | 柜体与存放；镜体表面；清洁登记 | ST-01、ST-03、ST-02；悬挂、柜内状态和登记分别判断 |
| 候诊区 | 座椅、隔断与两侧通道 | WT-01；小型章节可以只有一幕，不为分幕增加步骤 |
| 消化/呼吸诊疗室 | 用途与设备；报告与历史记录；台面与废物 | 两室分别覆盖CL-01–CL-04；方法可复用，证据和结果不互相代签 |
| 清洗消毒室 | 空间与工位；设备与工具；水路与视频；人员防护；产品资料；附件与逐次测漏 | RE-01、RE-02、RE-03、RE-06、RE-04、RE-05；保留全部子项 |
| 办公室最终 | 本次发现、回查修改、统一提交与只读复盘 | 同一办公室与同一会话；不新建独立成绩副本 |

#### EX01 引导式探索与弧形入口

- 安小卫推荐一个当前目标，用户可选择本幕其他可用对象。推荐标记不表示答案、合格或强制锁定。
- 同屏仅提供当前主题的少量入口；入口固定在前方及左右手可达弧形区域，按对象方向组织，不要求伸手触碰远处物体、不把必需入口放在身后。最终数量和布局由坐站可达性验证确定。
- 入口名称直接表达动作，如“查看柜内”“查看清洁登记”“检查镜体”。不使用“下一细项”作为主要玩法；单条内容无前后翻页，多条内容到末项不循环回首项。
- 选择后收起其他入口；观察界面可返回主题选择，主题回查入口仍可找到。不同时展开环绕菜单、完整对话和资料主面板争抢输入。
- 用户选择其他对象时安小卫就地带教。仅有可说明的业务前置依赖才引导先学，不因偏离推荐顺序强制返回。

#### EX02 完整现场与场景交接

- 所有检查点保留房间上下文；柜体、隔断、设备保持实际场景关系，不切到虚空展台。小物件通过真实手部抓取近看；资料展开为固定可读视图，关闭后回到原检查上下文。
- 房间交接采用“当前界面收起—渐暗—遮黑换景—揭幕呈现场景—简短引导”的节奏。房间名和当前目标可短暂呈现，不能堆进度列表；场景、巨大面板和角色不得同时突兀弹出。
- 同房检查点切换采用较轻过渡；主题变化但观察位未变时，不强制遮黑或重新加载房间。回查缩短首次介绍，不强制重复示范。
- 不飞行、不模拟走路、不转动玩家视角，不让房间或菜单环绕旋转。环境位移/朝向仅在遮黑期间调整，头手1:1；观察、阅读和翻页时世界固定，面板不跟头、不反复回中。
- 切房先停止媒体与交互、解绑并销毁旧房对象、释放独占资源，再加载目标；不预加载下一房。共有轻量过渡UI可以常驻。
- 重复触碰只接受一次有效请求。头部追踪未就绪保持转场等待，不以计时伪造成功；丢手暂停手部输入，恢复不重复记录。目标加载失败清理失败对象，保留会话并提供重试或恢复原房间的可行入口；恢复仍遵守单房加载。
- 不为演出故意延长等待。具体渐隐时长、揭幕曲线和构图属于待验证设计参数，不能宣称已获得舒适性或性能验收。

#### EX03 安小卫对话与界面

- 新流程必须实际驱动小精灵专属文本框，覆盖入幕目标、必要方法示范、操作反馈、请求提示和离幕小结；仅创建对话组件或显示角色不算接入。
- 文本框含明确的安小卫身份、当前短正文及必要动作；随实际内容调整高度。短文本不保留大块图片占位，长文本按意思分段，不靠缩小字号塞入固定大板。
- 台词完整呈现，不要求每句话点击“继续”，不计时强制消失。用户执行对应动作后收成短提示；无动作可承接的反馈保留到主动选择下一步，完整提示可重新查看。
- 区分对话、资料、现场观察三种界面：对话短而集中；表格/纸面/电子屏占查阅视图主要面积；观察时仅留必要提示和返回动作。必要分段讲解才出现“继续”。
- 有效操作就地给轻量反馈，用户可以继续观察，不自动换检查点、主题或房间。按钮按压、选中和不可用状态一致清楚，不能仅用颜色区分状态。
- 使用自然语言与具体动作名。内部编号、路径、版本、开发进度、实现机制和来源差异解释只进文档/日志，不原样显示blockedReason或unavailableReason。
- 保留简短而真实的“模拟训练记录”“教学示意图”“本项暂不可用”“加载失败，请重试”。资料的对象、日期、来源及适用依据在相关查阅/判断处可见，不以清理文案为由删除必要证据。
- 场景、动画、角色、按钮及其他媒体保持静音；RE-03指定片段按用户要求保留原声。对话与主操作区均需通过坐姿/站姿可读、可达、无遮挡检查。

#### EX04 教学、自动记录与提示重试

- 首次遇到一种检查方法时结合当前对象简短示范；后续类似任务先让用户尝试，随时可请求提示。方法已介绍与任务已掌握分别记录，不因另一个房间学过方法就签收当前任务。
- 开门、选中资料字段等已验证的有效行为自动记录，不再额外要求点击通用“记录已查阅”。仅打开资料可记录打开事实，不能等同完整阅读、核查完成或判断正确；不按停留时间、视线或动画结束自动完成。
- 每项任务仍按自己的有效操作、证据和判断条件完成；自动记录行为、即时教学反馈与办公室统一提交是三个不同事件。去重以任务/子项和有效行为为依据，不因重开界面或迟到回调累加。
- 用户判断错误时先提示值得重新观察的位置，不立即公布完整答案；允许重新查看、修改判断或主动查看完整讲解。用户可跳过或暂留未答，不因答错锁住后续房间。
- 请求讲解可以在统一提交前发生。本条替代旧独立考核的“提交前一律不反馈对错/答案”限制；保留最终统一提交和只读规则，不恢复独立考核模式。
- 看过示范、请求提示/讲解与自主判断应可区分；讲解不能自动替用户填答、把首次错误抹成一次答对，或将仅看答案标成独立掌握。记录提示使用与判断修订的最小事实，不引入新评分或资格认证规则。
- 缺件、证据不足或适用依据未核实时，说明无法完成相应判断，不生成错误提示、不扣作学员过失、不自动评合规。所有医学解释必须可追溯到适用依据。
- 同次会话保留主题位置、已看证据、方法示范、提示使用与判断修订；重启清空。提交后允许只读回看材料与已有讲解，不新记操作、答题或修改结果。

#### EX05 美术资源与信息呈现

先核对[图册](full-script-visuals/ASSET_CATALOG.md)及已有资源绑定，再按具体检查内容补图、材质和模型。适合生图的内容包括教学局部示意、经依据核对的状态对照、表面纹理和纸面外观；每项登记来源/提示词、用途、哈希、运行消费者与验证结果。

医疗记录保留原稿的表格结构、字段关系及电子/纸质载体，准确业务字符和数据由同源数据呈现。生成图不能冒充医院原表、实拍、检测或产品凭证。悬挂镜体、附件和人员防护交互须有相符对象；图片不能替代必需三维操作，生图不能补造指定视频和医疗依据。不得以增加装饰图来填补固定面板空白，或将弧形选择做成包围玩家的长列表。

## 12. 完整体验流程（历史v2业务编排）

本节保留来源和业务拆分追溯。步行、门口切房、双模式、魔法书/手掌开场、旧课程前置与高斯表述已被现行规则取代，不得用于实施。当前流程按第7.2节执行，业务对象和证据未被取消。

以下顺序是按新稿主线、旧稿补项及现有模型制定的工程编排；除已实现切片外均为待实现目标。门位置与站点坐标须由实物几何和实际活动区共同决定，不将示意顺序直接转成穿墙直线。

```text
大厅：手掌开场 → 安小卫简报 → 选模式 → 实际走到门口
  ↓ 近触切房
办公室：整体观察 → 电脑记录 → 纸质台账/产品档案 → 房间小结 → 门口
  ↓
储存库：柜外 → 开柜与悬挂状态 → 镜体表面 → 柜侧记录 → 门口
  ↓
候诊区：座椅布局 → 实体隔断 → 两侧通道关系 → 门口
  ↓
诊疗区：消化室（设备/报告/记录/台面及废物）→ 门口切换

  ↓
洗消室：隔断与关门 → 工位/分设 → 设备与毛刷 → 用水/指定视频

  ↓
原办公室：汇总 → 可回查修改 → 明确统一提交 → 只读复盘 → 结束
```

### 12.1 大厅与两模式进入

- 保留开场同款安小卫/魔法书发光手印与完整手掌操作步骤，首次可靠追踪固定入口；不是以切换房间重播整个开场。
- 开场分操作提示、简报、选择模式三段。简报解释“点位、方法、依据条款、法律责任”；具体法律文本无来源时不展示编造责任。
- 入口只有“开始学习”，简报阅读不计分，无模式切换。
- 完成选择后主动跟随向导去门口；近触前往办公室。大厅可接用户高斯小样，但先验证格式/平移观察/遮挡/性能；不以接入不明格式为由删除大厅流程。

### 12.2 办公室：两次访问、同一房间

首次：`OF-00`整体观察 → `OF-01`电脑 → `OF-02`测漏 → `OF-03`生物学监测 → `OF-04`消毒剂监测与产品档案 → `OF-05`培训与六类资料总核查。

- OF-00为场景观察子组，不挤占新稿“办公室五关”：能看到办公桌、文件柜、打印机、电脑；文件与柜门状态可查。现有OfficeRoom有多工位与椅子，选定一个主核查工位，其他工位不强制重复核查。柜子/打印机是否有可用实体需逐对象确认。
- 走到真实电脑前，近触屏幕进入操作；实体屏与放大视图读取同一记录数据，登录画面只作外观，不增加真实账号验证。蓝白医院系统样式，不能把大块深色问题卡当作最终电脑。
- OF-01按日期/镜号切换至少一个完整样例与一个可从全表判断的训练情境。四组内六字段单独有锚点：日期、患者标识、镜号、开始时间、结束时间、人员。显示查询范围和总条数，不能截掉字段后冒充缺项。
- 文件资料在电脑或实际文件夹上进入固定可读视图；六类材料均有正文、来源/模拟标识、范围、对象编号；“打开封面”不是“核查完成”。产品档案与洗消瓶体共享产品ID，不能把未核验瓶身文字当真实备案。
- 当前带教按EX04首次简短示范、随后尝试；错误先提示，玩家可主动请求完整讲解，不沿用旧独立核查的提交前禁反馈限制。对跨房核查疑点保存证据引用，允许后续回来修改。

### 12.3 储存与候诊
