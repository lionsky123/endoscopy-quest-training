# Oppy Fairy source notice

Source: Meta `Unity-TheWorldBeyond`, commit
`d13df1eb9f3b2d134d0282fb557b9826108598b6`.

Upstream: <https://github.com/oculus-samples/Unity-TheWorldBeyond>

The imported production closure keeps Meta's original Oppy model/Avatar,
external material GUIDs, lighting ramp, body/eye textures, and the authored
`idle_stand`, `walk_start`, `walk_loop`, `walk_stop`, `reaction_waveHand`,
`reaction_like_start`, `reaction_like_loop`, `reaction_like_stop`,
`reaction_wonder`, `reaction_powerUp`, `jump_intro`, and `jump_outro`
animation clips. The remaining sample animation library is
not copied because it is unused and would add roughly one gigabyte of source
assets.

Adaptations for this project:

- `ToonFoggyOppy.shader` retains the source texture/ramp/half-Lambert/glow
  treatment but uses the project's URP 17 forward path; sample-room cubemap fog
  is removed because Visitor runs in Passthrough rather than the sample's
  virtual room.
- Sample-only animation events (`PlaySound`, `PlayPowerUp`, `GoToUFO`) are
  removed. Their target is `VirtualPet`, which is deliberately not imported.
- A small project-owned Animator Controller preserves the original Oppy
  discovery chain: random `Like`/`Wave` can transition directly into the
  source `Wonder` state when the shell releases. `Like` and `PowerUp` remain
  mapped to Fairy interaction and celebration semantics. The source Jump chain
  is retained for future semantic use but is not the first-arrival action.
- The clean Fairy Prefab keeps the reference model scale (`0.03`), imported
  PetRoot `+Z` travel direction, and aligns the rendered feet to local `Y=0`.
  Movement continues to drive the reference `Running` semantic, while the
  application-global Fairy owner supplies the destination and floor height.
- `VirtualPet`, `WorldBeyondManager`, NavMesh, BoneSim, thought
  bubbles, and sample story state are not production dependencies.

# Dialogue portraits

`Portraits/OppyListening.png`, `OppyWelcome.png`, and `OppyWonder.png` are offline renders of the approved Oppy model and its existing animations, generated by `OppyFairyAssetBuilder`. They inherit the source attribution and license referenced above. They are static dialogue assets; the visitor runtime does not create another model or portrait camera.

The local arrival reuses the already imported other-world ambient loop and pollen texture. Pollen uses a bounded 48-particle instance, a project-owned material with portal stencil equality, and the existing Oppy particle shader. The shader defaults to Always for ordinary companion/reveal effects; only window pollen opts into clipping.
