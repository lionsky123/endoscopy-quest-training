# Fairy Arrival Reference Assets

Source: Meta `Unity-TheWorldBeyond`, commit
`d13df1eb9f3b2d134d0282fb557b9826108598b6`.

Upstream: <https://github.com/oculus-samples/Unity-TheWorldBeyond>

The production arrival closure retains the source assets and original Unity
GUIDs for:

- `OppyDimensionJump.prefab` (`WorldShockwave` in the source scene)
- `DimensionRing.mat`, `ShockRing.tga`
- `VRFlashlight.shader`, `VRFlashlight.mat`, `FlashlightGlow.tga`
- the Oppy `PassthroughShell` sphere dimensions and `StandardPassthrough`
  blend/depth contract
- `White.tga`
- `MT_Flashlight_Flicker.wav` and `MT_Malfunction.wav`
- `OppyTeleportParticles.prefab`, `OppySparkles.prefab`, their original
  particle Shader/materials, `chargeRing.png`, and `StarParticles2.tga`
- `VRFlashlightQuad.fbx`, `LightconeMesh.fbx`, `LightconeGlow.shader`,
  `LightconeGlow.mat`, and `FlashlightCloud.tga` from the source
  `MultiToyFlashlight` visual closure
- the source `BackgroundEnvironment` Prefab, nested visual Prefabs, meshes,
  materials and textures, plus `ToonFoggy`, `ToonFoggyClouds`, and `ToonSky`
- `Amb_EnvAlienLp_01_Right.wav` and `WorldBeyondAudioMixer.mixer`, retained as
  dependencies of the byte-identical source environment

The pinned upstream environment inputs contain 13 missing MonoBehaviour
components for absent script GUID `85eee4a073f3ef344b70e1a1e3a2fa18`:
seven in `BackgroundEnvironment/Environment.prefab` and one in each of
`ForegroundFlower.prefab`, `ForegroundGrass.prefab`, `rock_01_prefab 1.prefab`,
`tree_01_prefab.prefab`, `tree_02_prefab.prefab`, and `tree_03_prefab.prefab`.
These are preserved as upstream provenance rather than repaired by editing
source YAML. `OppyFairyAssetBuilder` removes missing scripts and all nonvisual
components before saving `OppyOtherWorldEnvironment.prefab`; production
dependency validation requires the generated Player closure to remain clean.

`OppyArrivalEffect.prefab` is generated by nesting those two official particle
Prefabs under the official `OppyDimensionJump` root. It introduces no
project-authored particle curves, colors, or textures. The generated variant
scales only the DimensionJump root and Glow particle sizes to 8% of source
(15 to 1.2, and 3 to 0.24). It uses unscaled particle time and explicit
controller cleanup; the source Prefab remains unchanged.

`OppyDiscoveryFlashlightAperture.prefab` recreates only the source
`MultiToy.prefab` flashlight hierarchy and source transforms. At runtime,
`FairyArrivalFlashlightAperture` ports the source `VirtualFlashlight` visual
core: four `VRFlashlightQuad` slices, the exact slice spacing/scale formulas,
viewer-facing billboards, `LightconeGlow` scrolling, and the original nine-key
`FlickerStrength` curve. The sample's `WorldBeyondManager.MainCamera` lookup is
replaced with the Visitor viewer explicitly supplied by Fairy; no input,
weapon, chapter, `RoomFramer`, or sample singleton code is retained.

`FairyArrivalDiscoveryMask.prefab` combines that official aperture and Oppy
PassthroughShell with a generated visual-only copy of the official background
environment. The source environment Prefab remains byte-identical; the three
source shaders retain their GUIDs and visual formulas but are ported from the
built-in pipeline to URP.

The source VirtualRoom normally hides the complete virtual environment and the
flashlight writes eye-buffer alpha to reveal it. Visitor has no opaque virtual
room because it is a full-passthrough botanical-garden scene. A small
project-owned stencil writer therefore limits both the official forest and
pre-transition Oppy to the outer official flashlight slice. Window geometry, mask texture, slice formulas,
flicker curve, environment art and Oppy art remain sourced
from The World Beyond. The application adapts the final reveal to a local
arrival and does not replay the sample's full-room Passthrough malfunction
or environment-light flicker. The window opens automatically; no flashlight input,
weapon, search counter, or first/second discovery is retained.

The ring starts before Oppy becomes visible, followed by the original
Like/Wave reaction, window close, and a short greeting. The configured
window reaction delay is 0.65 seconds; Active is published only after local
effect cleanup. The shader preserves source color and has no `_RiftColor`.
See `docs/changes/2026-09-08-fairy-local-arrival.md` for this approved adaptation.

The source project sets
`OVRManager.eyeFovPremultipliedAlphaModeEnabled = false` for the reversible
PassthroughShell/VRFlashlight alpha pair. Meta XR SDK 201 normally requires
premultiplied alpha, so this project snapshots that setting, uses the source
mode only for the one-shot Fairy arrival, and restores it on success,
Panorama suppression, Hide, Close, failure, or destruction. This scoped mode
switch is the only render-pipeline compatibility seam; Quest validation is
required because desktop rendering cannot prove eye-layer compositing.

The imported closure intentionally excludes the sample's full chapter system,
MultiToy gameplay/input and shell model, and VirtualRoom manager.
Visitor already owns the MRUK room and full Passthrough layer. Bootstrap
explicitly supplies that layer and the Visitor environment light so Fairy
never discovers global scene objects.
